# 09 — Tracing GC

本册讲 zjs 的**生产收集器**：非移动、sticky-mark-bit 分代、增量标记、停世界。引用计数已退役。语义权威仍是 ECMA-262；QuickJS 只是对照。现行不变量见 [gc-invariants.md](../gc-invariants.md)；函数级展开以本册源码为准。

`gc.zig` 是 Registry 枢纽，与 block heap / trace / conservative / memory 分工，所以拆成子文件。本文件只讲地图、类型合同、一次收集怎么走。

## 几何：superblock / block / cell

```
2 MiB superblock
 └── 32 × 64 KiB block（每个 block 一种 size class）
      ├── 112 B Block 头（钉死）
      ├── 四张 bitmap（alloc / mark / doomed-or-remember / finalizerBits）
      └── 定长 cell：[8 B Metadata prefix][payload]
```

- **superblock**：`gc_block_heap.superblock_bytes = 2 MiB`。classed 切成 32 个 64 KiB block；medium 把整页当 run；tombstone 槽位保留（`super_index` 是数组下标，不能 compact）。
- **block**：一种 size class，`block_magic` 在头。空 block 回 runtime 空闲链；映射只在整个 superblock 释放。禁止「一块超大 mmap + 按 block munmap」。
- **cell**：`gc_space.classes` 生成的 size class（线性 16..128，再 `nextGeometricClass` 到冻结的 `measured_max_small_payload = 3760`）。payload + 8 字节 prefix 必须能在 64 KiB 里放下至少 `min_cells_per_block = 16` 个。
- **extent**：超过 cell 上限、不到 64 KiB 的走 medium 页 run；≥ 64 KiB 走 large 独立映射。Object 永不走 extent；rope 节点 comptime 断言永远塞进 cell。

## 四张 bitmap

每个 classed block 的 geometry（`blockGeometry`）把四张 word 数组排在头后面、cell 前面：

| 列 | 偏移 | 含义 |
| --- | --- | --- |
| **alloc** | `alloc_bits_off` | 这个 cell 是否已交给分配器。死亡的普通对象只清这一位。 |
| **mark** | `mark_bits_off` | 当前 heap `mark_epoch` 下是否标活。epoch 过期 ⇒ 整张表读成未标。 |
| **remember / doomed** | `remember_bits_off` | 字段名仍为remember，当前回收路径用它保存doomed位；`snapshotDoomed`建立当前condemnation快照。它不是Registry的权威remembered owner哈希表，读doomed须遵守窗口/缓存有效性合同。 |
| **finalizerBits** | `remember + words*8`（不进 Block 头，保持 112 B） | `needs_finalizer`。sweep 只对 `doomed & finalizer` 调析构；其余 `alloc &= ~doomed`。 |

非 block 载体（Shape / Realm / Module / bytecode / VarRef / BigInt）没有这四张表：mark 在 `Metadata.lifetime.mark_epoch`，condemnation 是保留值 `condemned_mark_epoch = 0xFFFF`。

## minor vs major

- **minor**（`collectMinor`）：只扫 young。根 + conservative 栈 + remembered owner（**force-trace，不 tryMark**——sticky 老 mark 会让 walk 跳过孩子）。活下来的 cell 由 `retireTracedYoung` 清 `flags.young`（sticky：不拷贝、不计数）。`young_trigger_count` 排除 owned storage cell（property/array/payload/string_buffer），否则对象长大会被当成新垃圾。
- **major**：`beginIncrementalCycle` 清 mark、seed 根、开 `major_marking_active`；`incrementalMarkStep` 按时间预算抽灰前沿；`finishIncrementalCycle` remark（再 seed 根 + conservative，因为 native 栈无 barrier）+ ephemeron + weak + condemn + sweep。同步 `collectCycles` 是同一套 `Collector.run`。
- **morgue**：condemn 之后切片析构。morgue 非空时 conservative 可能扫到尸体，所以 `shadeExact` 拒绝 `headerCondemned`。Registry 的 minor 策略查询没有 morgue 判定，但 runtime.pollGC 当前优先运行析构切片并返回；不能据此声称普通 poll 会在 morgue 非空时发起 minor。

## conservative scan

生产收集通常扫native栈和寄存器（`spillRegistersAndScan`）；精确声明根也参与正常收集。候选字不会未经成员验证就当header解引用：`address_registry.forEachTraceCandidateAt` 用几何（block / arena / extent 页索引）+ `heap_accounted` 验证。`-Dzjs_gc_roots_diag`启用附加根诊断，不表示普通构建没有精确根。host 静止的 teardown 可以关 conservative，避免栈残字钉住已释放的 Realm。

## pins / scheduler / MemoryAccount

- **pins**：`gc_registry_pins.Ledger` 是「收集器不得回收」的权威。宿主 pin 是正计数；`construction_pin_count = maxInt(usize)` 保护未 publish 的 generator shell（无 Shape，trace 走不进去）。
- **scheduler**：`gc_registry_scheduler.Scheduler`包含Policy、major phase/reason、单个request latch及host_quiescent。后续request可升级urgency并替换reason、替换原allocation_threshold reason或填补空reason；不是逐请求排队。
- **MemoryAccount**：所有经账户的分配。普通分配器不逐笔触发GC；Object以及字符串body/rope分配共用collectBeforeObjectAllocation边界，pollGC也重新检查阈值。slab 是 4 KiB 自对齐 arena，给 conservative 算术解析。

## 三条收集路径

以下是主要成功路径；错误处理和审计分支详见函数章节，不能把三者合成同一固定顺序。

- **minor**：检查minorsAllowed及young population；打开minor retirement，清young marks，seed精确根和按配置启用的保守根，force-trace remembered owners，drain并处理ephemeron。随后检查addressSetWhole；失败时bulk promotion并关闭young generation，返回0。成功则sweepUnmarkedYoung，关闭young generation并执行对应销毁工作，记录yield/诊断。minor不执行major的processWeak和sweepAtomTable。
- **同步major**：collectCycles打开major retirement，Collector.run清全堆mark（block heap epoch步长2、header epoch另推进），seed并drain精确根，再按需seed并drain保守根，处理ephemeron、weak。地址索引完整才进入sweepUnmarked；其中完成condemnation与同暂停销毁，随后sweepAtomTable。外层clearYoungState并commit retirement；若因地址不完整跳过sweep，则abandon retirement并请求后续major修复。
- **增量major**：begin准备前沿、打开retirement、清mark、seed精确/保守根并检查前沿失败，清young block链与remembered/census，再启用marking及屏障门控。mark step按预算处理前沿；finish再次seed根，drain本地及barrier前沿，处理ephemeron，关闭marking并验证前沿已空，再processWeak。addressSetWhole失败时abandon并请求修复，返回0；weak处理已发生，不能称作完全无副作用。成功时snapshot block doomed、回收死extent、condemn list/side Objects并设置morgue，接着在同一暂停内sweepAtomTable，clearYoungState并commit。需要资源析构的morgue成员留待后续切片，不能把finish等同全部析构完成。

标记成功不等于所有边已扫描：storage leaf、同步Shape/Realm和construction root各有专用路径。强remembered owner重扫也不同于普通tryMark。GC不移动幸存者来完成promotion，但Shape结构自身可因mutator扩展迁移，因此不能把“非移动GC”解读为所有内部指针永不变化。

## `gc.zig` 文件级类型（函数在 09-gc-registry.md）

`gc.zig` 是 Registry 声明处，把 pins / lists / heap tokens / diagnostics / incremental / generation / mark queue re-export 进来。布局合同：`Registry.hot` 必须在 offset 0、`align(64)`，`phase` 与 `barrier_gate` 同在第一缓存行。当前布局断言不应与已经退役的RC release热路径混为一谈。

### 前缀与 kind

- `RefKind` / `GcKind`：4-bit，低 nibble of flags byte。0 = object（热路径 `tst`）。S4 加了 property_storage(8)、array_storage(9)、payload(10)、rope(11)、string_buffer(12)。
- `Metadata`：8 字节 extern，`memory.zig` 按偏移手写，**禁止改字段序**。`size_class` / `alloc_info` / `flags` / `lifetime`。
- `AllocInfo`：`block_size_idx:u5`、一位reserved、`heap_accounted`、`standalone`。`0x1F` 是 block cell 标记。
- `BlockFlags`：kind + young + finalizing + needs_finalizer + reserved。
- `TraceHeader`：普通非Object list载体的8字节侵入后继；string/rope/storage等prefix载体也不能使用该链字。Object 终端布局 M 的 handle **等于** body 指针（`bodyOffsetFromHeader(.object) == 0`）。`Header` 是它的别名，也是全 kind 统一的收集器手柄（`Metadata` 在手柄 −8）。
- `HotWords`：`phase` + `barrier_gate`。gate 是 `barrier_skip_bits`（young | remembered）或 0（major marking / `--gc-stats`）。

### 调度与错误

- `Policy`：large 阈值、external weight、RSS/cgroup 软硬限。
- `Request` / `RequestReason` / `RequestUrgency` / `SchedulerPoint` / `MajorPhase`。
- `CollectionError`：`OutOfMemory`、`PayloadMarkFailed`。
- `InvariantError`：list / young_head / pin / remembered cache / 存储 cell 悬挂等。

### 诊断开关（进程全局，每次Registry.init调用readStressFromEnv）

`ZJS_GC_STRESS`、`ZJS_MINOR_AUDIT`、`ZJS_ATOM_AUDIT`、`ZJS_GC_ARENA_AUDIT`、`ZJS_GC_VERIFY_MINOR`、`ZJS_GC_VERIFY_MAJOR_ALL`、`ZJS_GC_M_CUT_INJECT`。
