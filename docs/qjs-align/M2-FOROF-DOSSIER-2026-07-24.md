# M2 for-of iterator 机制档案（workflow lane 侦查，2026-07-24）

## 机制总账

【总机制图】for-of-bytecode-next-zero-arg-2m：zjs 2565.0M insn/451.2M cyc vs qjs 1703.6M/280.4M（best-of-5 min）= 1.506x insn / 1.609x cyc；每迭代 zjs 1282.5 insn/225.6 cyc vs qjs 851.8/140.2。ZJS_DISASM=1 与 qjs dump 构建双侧字节码逐 op 一致（caller 每迭代 9 op：put_loc8/get_loc_check×2/add/push_0/or/put_loc_check/for_of_next/if_false8；next() 体 11 op：get_var_ref_check×5/strict_eq/if_false8/post_inc/put_var_ref_check/put_field/return）——发码层零差异，430 insn/iter 的 gap 全在 per-op 成本与调用/返回机制。zjs 的 for-of 调用是「半 supernode」：入口侧已同链（op_for_of_next → pushBorrowedIteratorNext → enterEntry 尾跳进 next() 体，无 driver 往返），但每迭代仍付：①入口资格链全量重证（forOfIteratorIndex 槽验证 + resolveInlineTarget 的 class-id 位集/fb flags/首 opcode/realm 检查 ~40-55 insn，qjs 只做 1 次 JS_IsUndefined + class_id 检查）；②generic pushFrame 记账（enterInlineCallDepthBytes 四计数器 23256/23272/24344/24368）+ 槽池 acquire + noinline setupBorrowedIteratorEntry bl（42/iter，qjs= alloca 1 条 + 7 个 sf 标量 store）；③Machine 多标量镜像再发布（vm.function/frame/stack/catch_target/code_base，qjs 全在递归 JS_CallInternal 的寄存器里）；④返回侧掉出 leaf 快臂：return_action==.for_of_next 走 Outcome→driver→op_post_call_continuation(19)→464B 帧的 completeForOfNextContinuation(291)，重做全套槽/类验证 + JSValue 经 q0 spill 过栈（store-forward 危害，insn 采样 15.6%+5.3% 磁石）+ 出线 bl toBoolean + 每-free 重载 ctx→runtime→gc-phase 字节；qjs 对应段是 JS_Call 返回后的直线 C（js_for_of_next 16697-16712 + IteratorNext done 臂 16607-16617），零重验证、值走寄存器。⑤体内 per-op：get_var_ref_check 21-24 insn（每 op 重载 vm.frame + len 界检 + VarRef 三跳链）vs qjs 12-15（var_refs 寄存器驻留、无界检）；put_var_ref_check 整个走 coldStd 发布壳(34)+varRefVm(22)+execPutVarRef(49)≈105/iter vs qjs 内联 ~12（且 zjs 每写付 const/function-name 的 closureVar 双查 + cell-adapter 检查，qjs 在 resolve_scope_var 编译期消掉 const 违写）。cycles 侧偏斜：op_for_of_next 14.82% cyc vs 10.26% insn、op_return 5.79% vs 2.55%——调用/返回链是 stall 大户，周期收益预期大于指令收益。测量口径警示：insn 事件的 per-symbol 采样有 stall-skid 偏置（opGetVarRef 采样 230 vs 静态数 106；completeForOfNext 291 vs 静态 ~182），段级承重数字以反汇编静态计数为准，采样份额标偏差。

## qjs 对照机制

qjs 每迭代在单条 C 调用链内完成，全部状态寄存器/C 栈驻留：①CASE(OP_for_of_next)（quickjs.c:18977-18986）：offset=-3-pc[0]、sf->cur_pc=pc、调 js_for_of_next、sp+=2——3 条 glue，不重验证 enum_rec。②js_for_of_next（16686-16712）：唯一检查 JS_IsUndefined(sp[offset])，然后 JS_IteratorNext(ctx, sp[offset], sp[offset+1], 0, NULL, &done)——iterator/method 直接从 sp 相对槽取，跨调用信任不复检。③JS_IteratorNext（16589-16621）→ JS_IteratorNext2（16548-16585）：method 非 C-iterator_next（16557-16571 的 JS_CFUNC_iterator_next 快臂不命中），走 obj=JS_Call(ctx,method,enum_obj,0,NULL)（16573）→ JS_Call（20717）→ JS_CallInternal C 递归（17746）：js_poll_interrupts（17787）、class_id 检查（17817）、b=p->u.func.function_bytecode、js_check_stack_overflow=C 栈指针比较 2-3 条（17845）、local_buf=alloca(alloca_size)（17846，本例 var_count=0/arg 借用 argv 故初始化循环 17864-65 空转）、sf 7 个标量 store + sf->prev_frame=rt->current_stack_frame; rt->current_stack_frame=sf（17869-70）、pc=b->byte_code_buf 直接进 dispatch——pc/sp/var_buf/var_refs/b 全是该递归实例的 C 局部变量。④next() 体：OP_get_var_ref_check（18655-18669）idx=get_u16、val=*var_refs[idx]->pvalue、uninit 检、dup、push ≈12 insn；OP_put_var_ref_check（18670-18682）TDZ+set_value ≈12（const 违写在 resolve_scope_var 编译期已变 throw，33325-33375）；OP_put_field（19177）→JS_SetPropertyInternal own-shape 命中；OP_return（18266）ret_val=*--sp; goto done。⑤done: 尾声（20699-20709）：var_ref_count==0 跳 close、local_buf..sp free 循环（体返回时操作数窗口空→空转）、rt->current_stack_frame=sf->prev_frame、C return——返回值走 x0/x1 寄存器对。⑥回到 JS_IteratorNext done==2 臂（16607-16617）：JS_GetProperty(obj,JS_ATOM_done)→JS_ToBoolFree→未 done 再 JS_GetProperty(obj,JS_ATOM_value)→JS_FreeValue(obj)（单 tag 检+rc--，无 gc-phase 载入）；⑦js_for_of_next 尾（16700-16711）：done 臂才改写 sp[offset]；sp[0]=value; sp[1]=JS_NewBool(done)；OP_for_of_next sp+=2、BREAK。每迭代实测 852 insn/140 cyc：调用+返回+双属性读 ≈ 590，体+循环 op ≈ 260。关键结构事实：qjs 也付每迭代完整 JS_Call 递归与 2 次全量 JS_GetPropertyInternal（各 62 insn）——zjs 的 inline shape probe 在此段反而更便宜；qjs 赢在（a）帧=alloca+7 store 无池/无记账，（b）op 手柄 10-15 insn 无 frame 重载/界检/发布，（c）返回后直线 C 零重验证，（d）free=5 insn 无 gc-phase 链。


## 刀设计（按 ROI 排序）

1. 刀1【put_var_ref_check 无帧快手柄】预期 −85~95 insn/iter（约 gap 的 20%），横切 CELL 家族（cell-set/write-short 基准，A0 矩阵 CELL ROI 37.8）。现状：唯一每迭代走 coldStd 发布壳的热 op（34+varRefVm 22+execPutVarRef 49=105/iter，cyc 9.0%），qjs quickjs.c:18670-18681 内联 ~12 insn。改法：镜像 opLocCheck/op_drop_fast 先例做 frameless 手柄——cell=frame.var_refs[idx]，TDZ tag 检，set_value（free 旧值前按 op_drop_fast 的 GC-window 契约先缩 stack len），uninit/const/function-name/cell-adapter 全部落 cold 表间接跳。第二段：审计 zjs parser 是否像 qjs resolve_scope_var（33325-33375）把 const 违写编译期变 throw——若是，execPutVarRef 的 closureVar 双查在此 op 上是死码可整段删。风险：set_value 的 free 触发 GC 时操作数窗口一致性（op_drop_fast 已给出发布顺序模板）；门禁：test262 全量 known13、force-GC 二进制、cell-* 4 基准、for-of ×3 交错 A/B

2. 刀2【for_of_next 返回续体 supernode 臂】预期 −70~100 insn/iter，cycles 收益预计超比例（op_return cyc 5.79% vs insn 2.55%、continuation q-spill 是采样磁石）。现状：return_action==.for_of_next 掉出 popAndResume 的 leaf 快臂 → Outcome→driver→op_post_call_continuation(19)→464B 帧 completeForOfNextContinuation(291)，qjs 对应是 JS_Call 返回后的直线 C（16607-16617+16700-16712）。改法五件套：(a)在 op_return/popAndResume 加 .for_of_next 臂（r26 leaf-continuation 先例），vm 字段仍热时就地 finish+尾跳 caller pc，删 driver 往返与 464B 帧重建——注意 W3-ENTRY continuation-publish 刀被拒的教训（valid-bit 版 for-of cyc +1.25%）：必须复用已加载的 return_action 字节做臂选择，不加新协议字段；(b)信任 borrowed-entry 不变量（『caller stack 在 moved/borrowed 方法帧运行期间 deliberately left untouched』已是 finishForOfNextResult 的文档契约）删 forOfIteratorIndex 重验证+catch-marker+iterator tag 复检 ~25 insn；(c)JSValue 传输标量化（loadValueAsIntPair 纪律已在同文件 return 路径落地）杀 0x11966c4-cc 的 q0 spill store-forward；(d)done 的 bool/int tag 快腿内联替代出线 bl toBoolean（qjs ToBoolFree 内联腿）；(e)free 段 runtime/gc-phase 载入 hoist 到单次。风险：IteratorClose-on-abrupt 契约（IteratorNext 在 close 区域外，iteratorNextCallSetupRecover 语义须保留）；abrupt 腿仍走权威路径；门禁：test262 iterator/generator 全量、force-GC、for-of×3 + 21 形态调用矩阵（r27/r28 失败模式=method/alloc cycles 越线）

3. 刀3【warm borrowed-iterator 入口 + 缓存门控资格链】预期 −60~90 insn/iter。现状：每迭代 generic pushFrame(.borrowed_iterator) 全价 = enterInlineCallDepthBytes 四计数器记账 + acquireSlot + noinline setupBorrowedIteratorEntry bl(42) + entry 字段重发布；且 op_for_of_next 的资格链（class 位集/fb flags/首 opcode 0x2b/realm）在 borrowed-entry 缓存比对（0x12561d0）之前每迭代全量重证。next() 形状=capture-leaf（argc0/var0/captures3）恰是调用战役 O2 家族。改法：tryPushBorrowedIteratorFast 镜像 tryPushCaptureLeafCallFast+r29 warm carve（carveActiveMarked 原位取窗、miss 纯净回落权威冷构造器）、r35 的单次 teardown-state 发布、arg/var/open=0 由 call_facts 静态证明跳过 memset；并把缓存比对提到资格链之前——命中缓存的 iterator/method 记录 ⇒ 跳过整段 resolveInlineTarget 重证直达 warm 帧。qjs 锚点：JS_CallInternal 17841-17871（alloca+7 store，无池无记账）。风险：X925『热臂绝不共享（含模板层）』——必须独立实例不并入 O1/O2 已收割臂；缓存失效正确性（Entry 槽被更深调用复用后的陈旧记录，比对须含 fb/callable 同一性）；门禁：全调用矩阵 21 形态 + for-of×3 + L1I refill 监控（W3-CAPTURE 曾触发 20.15M L1I 灾难的先例）

4. 刀4【get_var_ref_check 头部瘦身】预期 −25~40 insn/iter（5 op×5-7 insn），同型收益横切所有闭包读密集负载（PROP-LOOKUP/CELL 家族）。现状 21-24 insn vs qjs 18655 的 12-15：多付 vm.frame 每-op 重载（2 load）+ var_refs len 界检（load+cmp+b）。改法：界检改编译期契约——FB finalize/resolve 时验证全部 var_ref idx < closure_var len（open_binding_idx 表先例；注意 memory 里 resolve_labels 四链同步脆性 W5 前科，改动须四链同步）；frame 重载消除受 4 寄存器 tail-ABI 限制（W3-CC 已证第 5 C-ABI 载体回退），只能靠缩依赖链（先 ldurh 操作数再单链 frame→ptr）。风险：手工字节码防御弱化——qjs 同样信任（对齐即忠实）；门禁：test262 known13 + ReleaseSafe 单测

5. 刀5【op_put_field 归因审计（先审后动）】采样 144/iter 但静态 ~52，且 qjs SetPropertyInternal own-shape 命中（19177→LTO 内联）估 60-80——可能已接近平价，采样超额是 probe-load stall skid。动作：先在 qjs 侧做 JS_CallInternal 内 PC 区间归因隔离 put_field 真实成本；若确有差，候选=receiver 验证去重（rc 头字节+class 位集与 op_for_of_next 资格链重复）与 free 段 gc-phase hoist（与刀2e 同型）。不做 IC/offset 缓存（qjs 无，换赛道红旗）

6. 【supernode 方向适配裁决】CALL-SUPERNODE-PLAN 终局（261 vs qjs 238 insn/call；54.7 vs 40.5 cyc）证明 leaf 家族形态收割是已验证路线、全单体已否决。for-of 的 borrowed 路径入口侧已是 supernode 形态（enterEntry 同链尾跳，无 driver 往返）——缺的是返回侧对称（刀2）与入口 warm 化（刀3），即把调用战役的 O2/r29/r26/r35 四件资产平移到 borrowed_iterator 家族。合计投影：刀1-4 共 −240~325 insn/iter ⇒ 1282→~960-1040 ≈ 1.13-1.22x insn（自 1.51x）；cycles 因返回链/q-spill/varRefVm bl 的 stall 集中，预期降幅更大但须按惯例只在交错 A/B cyc 数据落地后宣告
