| 阈值 | 实测 | 判定 |

**裁决：进入 P4 PlainEntry prototype。**

### 支持性证据（不只是阈值）

1. Return 仍占剩余差距 68%，而其中**最大的可结构性消除项不是字段访问，
   是 `op_return` 自身的 208 字节帧**（0.75 ns/call，12.72%）——
   它之所以存在，正是因为普通返回与全部特殊完成形态共用一个函数。
2. P3-11 / P3-12 已经证明普通路径**可以**与特殊完成分离，且分离本身零回退。
   PlainEntry 是把这一分离从控制流推进到数据布局。
3. Body 差距只有 +1.10 ns（17%），继续折腾 opcode 的边际收益低于 frame 方向。
4. RC/release 6.65% 且 qjs 做同样的释放循环 —— 不是 zjs-only 税。

### 负结果与设计修正（同样是产出）

- **P3-08**：`.operand` 内联 exact-frame setup —— 回退。移除动态证明每次调用
  都存在的 `bl` 只拿回 4.18 ns 台阶中的 0.68 ns，证伪了「台阶=调用边界」。
- **`ReturnMode` 字段**：+600 字节落在 `align(64)` 调用 handler → `call_body_loop`
  +1.53%、`fib_rec` +0.63%（4/4）。同样的信息改成派生后，`call_body_loop` **改善 0.79%**。
- **`cold == null` 不是 extended completion 的判定源**：六种 extended 形态中
  四种 `cold == null`，而 `arguments` 又会在普通完成的帧上设置它，两个方向都不成立。
- **`ownership.storage` 不可静态化**：校准断言在几分钟内抓到发布时 `borrowed`、
  退栈时 `owned` 的帧。
