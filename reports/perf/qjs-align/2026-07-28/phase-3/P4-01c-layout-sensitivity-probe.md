# P4-01c — Layout 敏感度证伪实验

- **日期**：2026-07-29
- **测量 HEAD**：`a8c5b843`
- **性质**：go/no-go 证伪，未改任何源码
- **结论**：**不敏感（≤0.24%）→ 不做 Frame/Stack 表示大改，转 P5 native-recursive prototype**
- **原始数据**：`P4-01c-results.json`

---

## 1. 实验设计与它能回答什么

源码、`Entry`、行为全部不变，只改 `-Dzjs_dossier_layout_pad`。
该选项在 `.text` 里发射 N 个互不可折叠的函数体
（`src/dossier_pad.zig`，`N=0` 时一字节不发）。

```text
P0..P4   pad = 0 / 16 / 32 / 64 / 96
```

它**能**回答：调用路径对整块代码落在内存何处是否敏感。
它**不能**回答：`Entry` 的 cache line 数是否是瓶颈 ——
pad 改变地址布局，缩小 Entry 减少的是 load/store 与数据 footprint，两者不是等价扰动。
本实验只作 go/no-go 用。

## 2. 结果

8 轮平衡交错，`--iterations 40 --warmup 5`，`checksums=1`。

| workload | pad0 | pad16 | pad32 | pad64 | pad96 | **极差** |
|---|---:|---:|---:|---:|---:|---:|
| `fib_rec` | 4.1850 | 4.1842 | 4.1925 | 4.1867 | 4.1861 | **0.20%** |
| `call_empty_0` | 7.1602 | 7.1544 | 7.1568 | 7.1581 | 7.1543 | **0.08%** |
| `call_identity_1` | 7.4842 | 7.4929 | 7.4751 | 7.4783 | 7.4894 | **0.24%** |
| `call_body_loop` | 11.8483 | 11.8526 | 11.8336 | 11.8455 | 11.8450 | **0.16%** |

相对 pad0 的偏移全部在 **±0.18%** 以内，且无单调趋势。

## 3. 扰动确实发生了

pad 不是空操作：

| pad | `.text` | `op_return` 地址位移 |
|---:|---:|---:|
| 0 | 3 723 740 | — |
| 16 | 3 725 800 | +448 B（7 行） |
| 32 | 3 727 848 | +896 B（14 行） |
| 64 | 3 731 944 | +1792 B（28 行） |
| 96 | 3 736 040 | +2688 B（42 行） |

`.text` 增长 2 060–12 300 字节，热符号地址移动 7–42 条 cache line，
**cache set index 被实际改变**。

⚠️ **但位移全部是 64 的整数倍**，因此 `op_return` 的行内偏移始终为 0，
且所有 handler 一起平移 —— **它们之间的相对距离不变**。

## 4. 这个实验覆盖与不覆盖的扰动类别

| 扰动类别 | 本实验 | 结果 |
|---|---|---|
| 绝对地址 / cache set 映射 | **覆盖** | **不敏感（≤0.24%）** |
| 单个 handler 体积增长导致后续符号相对位移 | **不覆盖**（所有符号同步平移） | 未知 |
| 数据侧 footprint（Entry 行数） | **不覆盖**（pad 只动 `.text`） | 未知 |

## 5. 裁决

按预设规则：

```text
fib_rec variation < 1%   ->  否定「call path 对布局高度敏感」
                         ->  不做 Frame/Stack 表示大改
                         ->  转 P5 native-recursive prototype
```

实测 **0.20%**，触发情况 A。

**不做 B（256 → 128，107 个消费者改动）。** 理由不是「Entry 缩小无价值」——
这个实验证明不了那个 —— 而是：**在没有任何证据表明 footprint 是瓶颈的情况下，
不应先支付 107 个消费者的改动成本**。这与本阶段已经三次生效的纪律一致
（P4-00 特殊状态、P4-01a extended 尾巴、P4-02.0 长度推导）。

同样**不做 A**（只删 `Stack` 的 16 B 全局字段）：它不跨 cache line、
不减少主要 load，是干净的 cleanup 但不是性能路线，
应作为后续顺手 refactor，不占 Phase 4 名额。

## 6. 一个需要谨慎对待的回溯问题

本实验把「绝对地址布局」的影响压到 0.24% 以内。而此前两处回退曾被归因为布局：

| 观测 | 当时归因 |
|---|---|
| P3-12.1 `ReturnMode` 字段：`call_body_loop` +1.53~1.70%（4/4） | 代码增长导致的布局位移 |
| P4-01a：`recursive_countdown_1` +0.78%（4/4） | `op_return` 缩小 1760 B 后的放置位移 |

⚠️ **不能据本实验断定那两处归因是错的。** 它们属于 §4 中「单个 handler 体积增长
导致后续符号相对位移」这一类，而本实验的所有符号是同步平移的，**不覆盖该类别**。

能说的只是：**「绝对地址布局」这一解释已被排除，那两处回退需要另一种解释** ——
最可能的替代是真实的 per-push / per-return 机制成本
（`ReturnMode` 那笔是每次 push 多一次分类与存储）。
这一点**尚未证明**，如果将来重启该方向应单独证伪。

## 7. 路线更新

```text
P4-01c  layout sensitivity probe        -> 不敏感，情况 A
            |
            +-- 不做 P4-02 Frame representation redesign
            +-- 不做 A（16 B cleanup 降为顺手 refactor）
            |
            v
P5  native-recursive prototype
```

### 为什么 native-recursive 现在是剩下最有依据的方向

Phase 3–4 的四次证伪把差距逐步逼到同一处：

| 轮次 | 排除了什么 |
|---|---|
| P4-00 | Entry 四条线不是特殊状态造成 |
| P4-01a | `op_return` 的 208 B 帧不是 extended 链造成 |
| P4-02.0 | 切片长度不是纯冗余，不能简单搬进 bytecode |
| **P4-01c** | **调用路径对代码地址布局不敏感** |

而 P3-13 的阶段分解仍然指着同一个地方：

```text
return   zjs 5.91 ns   qjs 1.54 ns   +4.37 ns   占差距 68%
```

qjs 的普通返回是 alloca 帧上的一次 C `return`，`done:` epilogue 在其
profile 中不可见；zjs 维护显式 Machine 帧栈，每次返回都要保存与恢复 caller 状态。
**剩余差距最可能来自 continuation 模型本身，而不是帧的字段数或字节数。**
P5 正是针对这一点的实验。

## 8. 限制

- 每个 pad 只建一个实例，未分离编译器双态（该效应此前实测约 0.4%，
  与本实验的 0.24% 极差同量级，因此**本实验只能给出「≤0.4% 量级」这一结论强度**）；
- pad 位移全部是 64 的整数倍，未采样行内偏移变化；
- 不覆盖相对位移与数据侧 footprint（见 §4）；
- 未测 `method_call_loop` 与非调用型 workload。
