# P6-01 — basecase 乘法写入拓扑：两刀合入

- **日期**：2026-07-29
- **裁决**：**两刀均合入**（`85be7dc6` 首行纯写、`641793d3` 短操作数作外层）
- **绝对定位**：`bigint/mul-multilimb` **zjs 20.587 → 12.976 ns/op**，对 qjs 9.733 **2.12x → 1.33x**

---

## 0. 归因先于改动（P6-00）

计划的第一刀是「HeapBigInt wrapper + limbs 单次 FAM 分配」。**该前提在本基准上不成立**：
两侧都只做一次分配（zjs `BigInt` 是值结构，`mulAlloc` 一次 `allocator.alloc`；
qjs `js_bigint_new` 本来就是 FAM）。FAM 方案的正当目标在 JS 层，
`bigint/mul-multilimb` 验证不了它 —— 降级为 **P6-02**。

profile 指出的真实 zjs-only 成本是**结果缓冲区预清零**（`memset` 7.58%）
与 harness 分配器（`malloc`+`free` 约 31%，非 BigInt 表示债）。

## 1. 基准本身的两次修正

| 修正 | 原因 |
|---|---|
| size loop 单独 checksum（混长度 + 首 limb + 末 limb） | 原 loop 只混 `limbs[0]`，各形状 checksum 全同，**测不出高位 carry 错误** |
| size loop 改为**固定操作数顺序** | 原 loop 按 checksum 奇偶交替 `mul(lhs,rhs)`/`mul(rhs,lhs)`，`1x8` 实为两方向平均 |

`AxB` 现在严格表示 `lhs.len = A`、`rhs.len = B`。

## 2. 第一刀：首行纯写，删除预清零（`85be7dc6`）

镜像 `quickjs.c:11401-11413` 的 `mp_mul_basecase`：第一趟 `mp_mul1` 覆写，
其后 `mp_add_mul1` 累加，因此 `js_bigint_new` 不清零。

| shape | P0 | P1 | 变化 |
|---|---:|---:|---:|
| `mul-multilimb` | 18.993 | 12.670 | **−33.3%** |
| `1x1` | 23.641 | 20.190 | −14.6% |
| `2x2` | 27.949 | 21.074 | −24.6% |
| `2x4` | 31.115 | 26.366 | −15.3% |
| `4x4` | 36.651 | 29.429 | −19.7% |
| `8x8` | 73.160 | 54.962 | −24.9% |

**远超 memset 的 7.58% 采样占比** —— 删掉预清零同时也删掉了第一趟对每个元素的读-改-写。
⚠️ 这再次印证第 3 刀的更正口径：采样占比是**局部显式成本估计，不是收益上界**，
这次是**低估**。

### 一处必须报告的偏离

首版实现**同时**换了循环嵌套方向。拆开单独测后：memset 是主因，
方向只在非对称形状有边际贡献。**合入的是只删 memset 的版本**，方向另立。

## 3. 第二刀：短操作数作外层（`641793d3`）

累加行数 = `outer.len − 1`，因此循环对操作数顺序敏感。有序矩阵实测：

```text
1x8  21.8 ns      8x1  26.6 ns      -> 22% 的顺序依赖悬崖
```

### 固定翻转（outer=rhs）被否决

| shape | 变化 | | shape | 变化 |
|---|---:|---|---|---:|
| `1x8` | **+23.61%** | | `8x1` | **−18.96%** |
| `2x4` | +5.75% | | `4x2` | −5.26% |
| `3x7` | +7.60% | | `7x3` | −6.77% |
| 对称四例 | ±0.36% | | | |

**完全对称的交换** —— 机制不是「哪个是 lhs」，而是「哪个更短」。**情况 B，不可合入。**

### 短者作外层：合入

| shape | P0 | P1c | 变化 |
|---|---:|---:|---:|
| `8x1` | 26.643 | 22.065 | **−17.18%** |
| `7x3` | 33.658 | 31.159 | **−7.43%** |
| `4x2` | 25.694 | 24.505 | **−4.63%** |
| `3x7` | 31.290 | 31.231 | −0.19% |
| `1x8` | 21.796 | 22.067 | **+1.24%** |
| `2x4` | 24.291 | 24.560 | **+1.11%** |
| `1x1` / `2x2` / `4x4` / `8x8` | — | — | +0.33 / +0.63 / +0.68 / +0.48% |

**改动后 `a*b` 与 `b*a` 成本相同**（1x8 22.067 / 8x1 22.065）。

**代价如实记录**：长度比较与两次切片选择对**每一次**乘法收费，
原本已快的顺序退 1.1–1.2%，对称形状退 0.3–0.7%。
合入理由是：消除 22% 的顺序依赖悬崖，值得在原本占优的一侧付约一个百分点。

## 4. 正确性门禁（两刀共用）

- **不变量写进代码**：第 0 行覆写 `limbs[0..inner.len]` 与其 carry 槽；
  第 i 行读取的最高位恰为前面各行已初始化到的位置；最高 limb 即使 carry 为零也显式写入；
- **poison 分配器测试**：0xa5 填充新分配 × 11 种形状 × 全 1 与单高位两种模式，
  对照测试内独立的零初始化参考实现。**注入故障验证有效**（去掉首行 carry 写入即失败）；
- **3000 组随机差分**对 Python 大整数，1–16 limbs，偏重全 `0xff`/稀疏/交替位，双符号，零不匹配；
- **跨引擎 diff** 与 pinned qjs 逐行相同；
- 全门禁绿：`test` / `test262-gate` / `test-oom` / `ReleaseSafe` / force-GC / focused / fmt。

## 5. 不外推

`2.12x → 1.33x` 只回答了「预清零与写入拓扑是否为真实固定税」。剩余仍可能来自：

```text
harness 分配器（P6-00 测得 malloc+free 约 31%，init.gpa vs js_malloc）
carry loop / helper codegen
normalize
result free
```

且矩阵只覆盖 1–8 limbs；更大操作数下乘法核心占比上升，结论可能变化。
