# P6-04a — BigInt 除法基线与动态拓扑

- **日期**：2026-07-29
- **HEAD**：`dbb4391a`
- **性质**：只做基准与计数，**未改生产代码**
- **结论**：成本**只由分子的比特长度决定**，每次除法约 **2.5 × 分子比特数** 次分配；
  除数宽度、归一化 shift 都几乎不影响 —— 与「逐 bit shift-subtract」的形态完全吻合

---

## 1. 现状实现

`src/libs/bigint.zig:533` `divRemAbsAlloc`：

```zig
var bit = lhs.bitLengthAbs();
while (bit > 0) {
    bit -= 1;
    const shifted = try remainder.shl(allocator, 1);   // 每 bit 一次分配
    remainder.deinit();                                 // 每 bit 一次释放
    remainder = shifted;
    if (lhs.testBit(bit)) try addSmallInPlace(&remainder, 1);
    if (compareAbs(remainder, rhs) != .lt) {
        const next_remainder = try subAbsAlloc(allocator, remainder, rhs);  // 又一次
        remainder.deinit();
        remainder = next_remainder;
        try setBit(&quotient, bit);                     // 可能 realloc
    }
}
```

对照 qjs（`quickjs.c` `js_bigint_divrem` / `mp_divnorm`）：归一化除数 → 逐 **limb** 估商 →
multiply-subtract + 有限修正。**逐 limb 对逐 bit，就是 64 倍的迭代数差，再乘上每次迭代的分配。**

## 2. 动态拓扑（gdb 静默断点，N = 1 / 21 取斜率）

每次除法的调用次数：

| shape | 分子 bits | `divRemAbsAlloc` | `BigInt.shl` | `subAbsAlloc` | **alloc** | **free** |
|---|---:|---:|---:|---:|---:|---:|
| `2×1` | 128 | 1 | **128** | 62 | **320** | 320 |
| `8×1` | 512 | 1 | **512** | 247 | **1273** | 1273 |
| `16×1` | 1024 | 1 | **1024** | 491 | **2541** | 2541 |
| `4×2` | 256 | 1 | **256** | 126 | **640** | 640 |
| `8×4` | 512 | 1 | **512** | 254 | **1278** | 1278 |
| `16×8` | 1024 | 1 | **1024** | 510 | **2554** | 2554 |
| `2×2` | 128 | 1 | 0 | 0 | 3 | 3 |
| `8×8` | 512 | 1 | 0 | 0 | 3 | 3 |

- **`shl` 调用数逐一等于分子的比特长度** —— 循环边界被直接测出来了；
- **分配数 ≈ 2.5 × 分子比特数**，与除数宽度无关；
- 最后两行是 `lhs < rhs` 的早退臂（JS 里 `a = 2^(A·64−1)+1`、`b = 2^(B·64−1)+3`，
  `A == B` 时 `a < b`），只有 3 次分配；
- 对照：**P6-03c 之后一次乘法是 1 次分配**。

```text
乘法   1 allocation/op                （= qjs）
除法   ~2.5 x numerator_bits alloc/op  （qjs 为 O(1)）
```

## 3. direct-core 基线矩阵（zjs-only，三次取中位）

`bigint/div-size-AxB` / `bigint/mod-size-AxB`，`iterations` 1000–3000。

| shape | div ns/op | mod ns/op | 分子 bits | ns/bit |
|---|---:|---:|---:|---:|
| `1×1` | 946.3 | 983.0 | 64 | 14.79 |
| `2×1` | 2111.6 | 2085.8 | 128 | 16.50 |
| `8×1` | 9206.9 | 9205.4 | 512 | 17.98 |
| `16×1` | 21194.0 | 21749.4 | 1024 | 20.70 |
| `2×2` | 2007.1 | 2007.6 | 128 | 15.68 |
| `4×2` | 4542.5 | 4498.0 | 256 | 17.74 |
| `8×4` | 10512.7 | 10558.9 | 512 | 20.53 |
| `8×8` | 10160.5 | 10126.9 | 512 | 19.84 |
| `16×8` | 26641.6 | 26728.5 | 1024 | 26.02 |
| `16×16` | 25770.9 | 25818.4 | 1024 | 25.17 |

- **横轴是分子比特数，不是除数宽度**：`8×1` 9.2 µs 与 `8×8` 10.2 µs 只差 10%，
  而 `8×4` 10.5 µs 与 `16×8` 26.6 µs 差 2.5 倍 —— 后者正是分子从 512 涨到 1024 bits；
- `ns/bit` 从 14.8 缓慢升到 26，是 `compareAbs` / `subAbsAlloc` 随除数变宽变贵；
- `div` 与 `mod` **成本相同**（两者都调用同一个 `divRemAbsAlloc` 再丢掉另一半），
  所以 `%` 不比 `/` 便宜。

⚠️ 这个矩阵会把分子的最高 limb 饱和。不这么做时 `lhs < rhs` 会**从伪随机模式里偶然掉出来**：
第一版跑出 `16×16` = 31 ns 对 `8×8` = 10 µs，测的是早退不是除法。

## 4. 归一化 shift 轴：当前完全无效

`sN` 后缀把除数的最高置位放在 `63 − N`，使一个会归一化的实现需要左移 `N` 位。

| case | div ns/op | mod ns/op |
|---|---:|---:|
| `8×4s0` | 10522.5 | 10511.8 |
| `8×4s1` | 10744.2 | 10672.9 |
| `8×4s32` | 10892.2 | 10944.4 |
| `8×4s63` | 10319.6 | 10336.2 |
| `8×8s0` | 10099.4 | 10132.3 |
| `8×8s1` | 10172.7 | 10131.2 |
| `8×8s32` | 10244.6 | 10236.0 |
| `8×8s63` | 10383.0 | 10376.8 |

**摆幅 ≤ 5%，无趋势** —— 当前算法根本不归一化，所以这条轴现在是惰性的。
**记录它正是为了 P6-04c**：Algorithm D 的 `qhat` 估计质量直接取决于归一化，
届时这条轴会变成活的，而基线已经在同样的轴上量过了。

## 5. 关系轴

`bigint/div-rel-*`，固定 8 limb ÷ 4 limb 形态（`lt` 用 3 limb 分子）。

| relation | div ns/op | mod ns/op | 说明 |
|---|---:|---:|---|
| `lt` | 26.0 | 35.6 | 早退，无循环 |
| `eq` | 4442.9 | 4464.5 | 商 1 余 0，仍走完 256 bit |
| `q1` | 4424.0 | 4452.7 | 商 1 余 1，同样走完 256 bit |
| `exact` | 10569.4 | 10581.1 | 余 0，512 bit 分子 |

**`eq` 与 `q1` 几乎相同**：即便商是 1，循环仍逐 bit 走完分子。
这直接证明成本与商的大小无关，只与分子长度有关。

## 7. 对 P6-04b / P6-04c 的判据

基线已经把两条判据的分母都固定下来：

```text
时间     8x1  9.2 us / 8x4 10.5 us / 16x8 26.6 us（direct-core）
         JS 层 255x / 243x / 209x / 152x
拓扑     alloc/op ~= 2.5 x numerator_bits
迭代     shl/op == numerator_bits
```

- **P6-04b（单 limb 除数）** 的目标形态是 `2×1` / `8×1` / `16×1`：
  `shl/op` 应从 128 / 512 / 1024 掉到 0，`alloc/op` 从 320 / 1273 / 2541 掉到 O(1)；
- **P6-04c（多 limb 除数）** 的目标形态是 `4×2` / `8×4` / `16×8`，
  并且 `sN` 轴届时会从惰性变为活跃；
- 关系轴的 `eq` / `q1` 是回归哨兵：逐 limb 实现下它们应该塌缩到接近 `lt` 的量级，
  逐 bit 实现下它们和 `exact` 同价。

## 8. 限制

- direct-core 矩阵是 **zjs-only**（与乘法尺寸矩阵同状态），没有 qjs 对照 harness；
  跨引擎数只来自 JS 层四个用例；
- 未计 `setBit` 与 `addSmallInPlace` 的单独调用数（它们在 `zjs` 二进制里没有独立符号，
  已被内联）；`alloc/op` 的总数包含了它们；
- 未拆分 `alloc/op` 中 `shl` / `subAbsAlloc` / `setBit` 各自的份额，
  只知道总量与分子比特数成正比；
- 未测负数与零除的路径（属于正确性门禁，不属于基线）；
- 未测 `pow`（它内部反复调用 `mulAlloc`，与除法无关）。
