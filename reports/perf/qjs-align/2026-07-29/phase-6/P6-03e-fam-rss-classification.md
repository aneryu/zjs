# P6-03e — FAM RSS classification：**上报的 RSS 上升不成立，是测量噪声**

- **日期**：2026-07-29
- **HEAD**：`c3c02cc5`
- **性质**：有界审计，只加一条回归测试，未改生产代码
- **裁决**：**分类为「不存在」** —— 同进程 A/B 证明 FAM 拓扑对 RSS 中性，
  standalone 形态反而更省。P6-03c dossier §7.1 的结论**是错的，本文更正它**

---

## 1. 需要更正的结论

P6-03c 的 §7.1 写：

> peak RSS 在每个 BigInt 形态上升 128–196 KB，非 BigInt 对照零差异，
> 与 GC 触发点前移一致（因果未确认）。

**这个结论不成立。**它建立在每个实例、每个形态**各一次** `maxRSS` 测量上，
而 `maxRSS` 在本机的重复测量摆幅就有约 200 KB —— 与所报的「效应」同量级。
「非 BigInt 对照零差异」也只是一次测量的巧合，不是谱系。

下面两组证据各自独立地否定它。

## 2. 证据一：同进程 A/B（决定性）

旧拓扑（`mulAlloc` + `createFromOwned`）在当前二进制里仍然可达，
所以两条路径可以在**同一个进程、同一个二进制**里交替跑 ——
构建差异、代码布局、页面分布全部被消掉。

探针在每个 `N` 上重建 runtime，跑 `N` 次乘法（每次立刻释放），
读 `/proc/self/statm` 与 `MemoryAccount` 的逻辑账：

| 拓扑 | shape | N=0 | 1 | 10 | 100 | 10 000 | 100 000 |
|---|---|---:|---:|---:|---:|---:|---:|
| OLD | `2×2`（slab class 10） | +0 | +4 | +44 | +116 | +116 | +116 |
| **FAM** | `2×2` | +0 | +4 | +44 | **+116** | **+116** | **+116** |
| OLD | `28×28`（slab class 30） | +0 | +4 | +44 | +116 | +116 | +116 |
| **FAM** | `28×28` | +0 | +4 | +44 | **+116** | **+116** | **+116** |
| OLD | `28×29` | +0 | +4 | +44 | +116 | +116 | +116 |
| **FAM** | `28×29`（standalone） | +0 | **+0** | **+0** | **+0** | **+0** | **+0** |

（RSS 增量，KB，相对该 runtime 循环前）

- **slab 形态两条路径逐 KB 相同**；
- **standalone 形态 FAM 是 +0，旧拓扑是 +116** —— FAM 在这里**更省**，
  因为它的乘积走 `rawAlloc` 直取，不再让 limb 块去碰 slab arena。

### 逻辑账（两条路径、所有 N）

| 量 | 结果 |
|---|---|
| `allocated_bytes` | 循环前后**完全相同**，且与 `N` 无关 |
| `allocation_count` | 同上 |
| `peak_allocation_count` | **FAM 6 / OLD 7** —— 少一个同时存活的分配，正是本刀的设计 |
| `major_gc_count` | 两条路径、所有 `N` 均为 **0** |
| runtime destroy 后 RSS | 与 `N` 无关，回到同一个值 |

## 3. 证据二：零 heap 乘法的负载同样有这个差

构造一个**完全不产生 heap 乘积**的负载（`3n * 5n`，两侧都是 short BigInt，
走 `shortBigIntBinary`，`createInlineUninitialized` 与 `mulAlloc` 都命中 0 次），
在 P6-03c 用的八个实例上各测 3 次：

```text
short-only（零 heap 乘法）        bigint_mul_2x2（每次 heap 乘法）
p0a  4740 4804 4676              p0a  4676 4804 4804
p0b  4800 4800 4668              p0b  4736 4660 4672
p0c  4676 4676 4804              p0c  4804 4676 4676
p0d  4800 4800 4672              p0d  4672 4660 4668
p1a  4868 4868 4868              p1a  4804 4868 4868
p1b  4856 4868 4868              p1b  4804 4868 4860
p1c  4672 4676 4676              p1c  4804 4668 4672
p1d  4868 4860 4804              p1d  4868 4864 4856
```

- 全体落在 **4660–4868 KB**，约 200 KB 的带宽；
- **同一个二进制、同一个负载内部就有 ~130 KB 的重复测量摆幅**（p0a 4740/4804/4676）；
- p1c 在两个负载上都落在 4670 附近，p0b/p0d 落在 4800 附近 —— 高低与 P0/P1 无关；
- 关键：**零 heap 乘法的负载上差值一样存在**。拓扑没跑，差却在。

## 4. 裁决（按 PRD 的四条判据）

| 判据 | 实测 | |
|---|---|---|
| RSS 差在首次运行后固定、logical live bytes 回零 | 是：N=100 起 RSS 增量恒为 +116（FAM slab）或 +0（FAM standalone），`allocated_bytes` 与 N 无关 | **记录即可** |
| RSS 随 N 增长 | **否** —— N=100 / 10 000 / 100 000 完全相同 | 不阻塞 |
| runtime destroy 后 `MemoryAccount` 非零 | **否** —— 逐字节归零 | 无正确性问题 |
| logical account 归零但 RSS 保留 | 是，且**两条路径完全相同** | 宿主 allocator 的物理保留，非 JS heap 泄漏 |

### slab class 还是 GC cadence

**两者都不是。**

- **GC cadence 被直接证伪**：所有 N、两条路径的 `major_gc_count` 都是 **0**。
  P6-03c 里「`triggerGCOnAllocation` 占 profile 2.10%」只说明触发**检查**在热路径上，
  不代表发生过收集；
- **slab class 效应存在，但两条路径同幅**：`2×2` 的 +116 KB 与 `28×28` 的 +116 KB
  在 OLD 与 FAM 上逐 KB 相同，说明它来自「每次迭代新建又归还一个 4 KiB arena、
  backing allocator 保留页面」这一既有行为，与乘积落在哪个 size class 无关；
- FAM 唯一改变 size class 归属的地方（`28×29` 进 standalone）**降低**了 RSS。

## 5. 结论

```text
P6-03c 的 FAM 拓扑对 peak RSS：
    slab-backed 乘积   中性（逐 KB 相同）
    standalone 乘积    更省（+0 vs +116 KB）
    与迭代次数无关，无泄漏，逻辑账逐字节归零
```

**P6-03e 关闭。**没有需要继续追的东西，也不再阻塞任何后续工作。

## 6. 留下的回归锁

探针本身不合入（它打印而不断言，且依赖 `/proc`）。留下的是一条断言版本：

`repeated heap multiplication retains nothing as the count grows`（`src/tests/core.zig`）

对 `N = 0 / 1 / 10 / 1000` 验证 `allocated_bytes`、`allocation_count` 循环前后不变，
且 `peak_allocation_count` 在 `N ≥ 1` 时**与 N 无关**（同时存活的乘积恒为 1）。
泄漏会在前者暴露，残留临时对象会在后者暴露。

## 7. 方法学教训

⚠️ **`maxRSS` 单次测量在本机的摆幅约 200 KB，不能用它去断言 100–200 KB 的效应。**
P6-03c 的 §7.1 正是这么做的，并且从「非 BigInt 对照恰好为 0」倒推出了一个不存在的
BigInt 特异性。正确做法在本文里：
**先做同进程 A/B**（消掉构建与布局），跨进程测量只用来交叉检查，
且必须有重复测量的摆幅作对照。

这与本项目既有的「固定二进制交错 A/B」纪律同源 ——
之前只把它用在时间上，没有用在内存上。

## 8. 限制

- 只测了 `2×2` / `28×28` / `28×29` 三个形态与 `mul`；
- `/proc/self/statm` 的 RSS 受页面回收时机影响，同进程 A/B 的 +116 KB 绝对值本身不可细究，
  可细究的是**两条路径之差**；
- 未在关闭 small slab 的诊断构建上复测 —— 同进程 A/B 已经把 slab 效应判为两路径共有，
  该对照不再必要。
