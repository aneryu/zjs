- **日期**：2026-07-30
- **P0**：`23610910`　**P1**：`5f255952`
- **裁决**：**分配目标精确达成**（`4 → 3`，`div`/`mod` 同时成立；单 limb 未动；

## 1. 机制

```zig
pub const DivOutput = enum { quotient, remainder, both };
```

从 `div` / `rem` 一路传到 `divRemAbsNormalizedLong`：
只要 remainder 就不分配商缓冲；只要 quotient 就跳过余数的长度扫描、分配与 unshift 拷贝。

**算法完全未动**：商位仍然逐个算出（除法本身需要），分子 scratch 仍然就地被消耗，
**只有最终构造不同**。

### 循环内**没有新增分支**

PRD 明确要求「循环内部不要 `if (want_q)`」。实现上不需要：
循环里本来就有 `j < quotient_len` 这个判断（用于跳过可证明为零的最高位），
把「有没有要商」折进同一个上界即可 —— 没有商缓冲时该上界是 0：

```zig
const q: []Limb = if (want_quotient) try allocator.alloc(Limb, quotient_len) else &.{};
const quotient_writes = q.len;          // 不要商时为 0
...
if (j < quotient_writes) q[j] = qhat else std.debug.assert(!want_quotient or qhat == 0);
```

`else` 分支在 ReleaseFast 下是空的。**每商位零新增分支。**

### 两处边界

- **单 limb 路径按 PRD 要求不动**：它已经是 2 次分配、且是矩阵里最快的形态，
  为省最多一次小分配去动它不划算；
- **`lhs < rhs` 早退臂纳入**：它唯一的分配就是被 `div` 丢掉的被除数克隆，
  属于同一个「不构造没被要的东西」机制。

## 10. 对 P6-04d2c 的建议：**期望值已经下降**

规划 d2c（合并 `u`/`v` scratch）时，分配数还是 6；现在是 **3**，其中两个是 scratch。
合并能省 1 次分配 / 1 次释放。

但 d2a 与 d2b 的数据都指向同一件事：

```text
固定成本主导的形态（rel-lt、2x2、8x8、16x16）
    d2a −17~35%，d2b −13~31%   ← 固定成本削减在这里最有效，且已被削了两轮
逐商位主导的形态（16x8、24x8）
    d2a −4~7%，  d2b −2.6~4.3% ← 每轮收益递减
```

`8×4` 现在是 108.3 ns，其中按 P6-04d0 的模型，5 个商位约 60 ns（12.0 ns × 5）——
**逐商位成本已占约 55%**，而 d2c 只动固定成本里剩下的一次分配。

建议在开 d2c 前**先重跑一次 P6-04d0 式的固定/逐商位拆分**，
用当前的 108.3 ns 重新定标；若固定成本已降到 45 ns 左右，
再省一次分配的上界大概是 5–8 ns（约 5%），**接近 d2b 在 `16×8` 上的实测水平**。

⚠️ 这只是**基于既有模型的外推，不是测量**。是否值得开 d2c 应由那次重标定决定。
