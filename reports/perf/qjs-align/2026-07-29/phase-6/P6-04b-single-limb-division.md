## 1. 机制

```zig
noinline fn divRemAbsByLimbAlloc(allocator, lhs, divisor) !struct { BigInt, BigInt }
```

从高到低一遍扫描，每个商位由「running remainder 与下一个 limb 拼成的 `u128`」除出来 ——
这是 qjs 对同一情形的形态（`mp_div1norm`，quickjs.c:11332），
也正是 `divRemSmallInPlace` 已经在做基数转换时用的内核，抬升到一个会分配的调用者。

**商的长度在扫描前就是精确已知的**：最高位商位是 `lhs_top / divisor`，
非零当且仅当 `lhs_top >= divisor`。所以缓冲区按最终长度分配，
**没有归一化 pass，也就没有收缩 realloc**。最多两次分配（商 + 非零余数）。
`lhs < rhs` 的早退在调用者里已经处理，因此商至少一个 limb。

## 2. 分配拓扑：O(bits) → O(1)

gdb 静默断点，N = 1 / 21 取斜率：

| shape | 分子 bits | | `shl` | `subAbsAlloc` | **alloc** |
|---|---:|---|---:|---:|---:|
| `2×1` | 128 | P0 → P1 | 128 → **0** | 62 → **0** | 320 → **4** |
| `8×1` | 512 | P0 → P1 | 512 → **0** | 247 → **0** | 1273 → **4** |
| `16×1` | 1024 | P0 → P1 | 1024 → **0** | 491 → **0** | 2541 → **4** |
| `4×2` | 256 | 未改动 | 256 | 126 | 640 |
| `8×4` | 512 | 未改动 | 512 | 254 | 1278 |
| `16×8` | 1024 | 未改动 | 1024 | 510 | 2554 |

**4 次分配与分子宽度无关** —— 常数，不再随比特数增长。

### 3.3 `noinline` 是被实测逼出来的

内联版让**共用同一个函数的多 limb 逐 bit 循环**慢约 2%：
`8x4` 1.0216、`16x8` 1.0212、`mod_8x4` 1.0235，**16 个组合全部 > 1.0**，
区间 [1.0089, 1.0289] —— 分布很紧，不是布局彩票。

加上调用边界后同一比较变成 0.9992 / 0.9970 / 1.0016，区间 [0.988, 1.011]。
快路径两个版本都是 gm 0.0091，**完全不受影响** ——
它已经比被替换的东西便宜两个数量级，一次调用相对而言是免费的。

## 6. 一处所有权模型隐患（本刀未修，且**不是**可达缺陷）

⚠️ **本节的原标题与定性已更正。**原文写「既有 double free，`test-oom` 未覆盖」——**过强**。

`divRemAbsAlloc` 的多 limb 尾部：

```zig
var quotient = BigInt{ .allocator = allocator };
errdefer quotient.deinit();
...
return .{ try normalize(quotient), try normalize(remainder) };
```

`normalize` 按值接收并**在自己失败时释放收到的 limbs**，
唯一的可失败点是收缩用的 `realloc`。调用者若还留着别名同一 slice 的 `errdefer`，
模式上就是双重释放。

**但那条失败分支是死的。**加计数器实测：这两次尾部 `normalize`
在 **2001 次除法中收缩 0 次** —— `subAbsAlloc` 每轮都已把余数归一化，
`setBit` 也让商的最高 limb 非零，所以 `len == owned.limbs.len`，`realloc` 根本不被调用。

正确定性：**这是一个不成立的所有权模型，不是一个动态可达的 double free。**
`ad6bd639` 做的是**模型加固**；随之加入的 fail-index sweep 的价值是
**向前的 OOM 合同**，不是对某个已修缺陷的回归测试。

## 7. 限制

- direct-core 的多 limb 比较无法判定（§3.4）；
- `1×1` 是 18.5x，低于门槛写的 20x —— 但门槛点名的是 `8×1`，那里是 75x；
- 归一化 shift 轴仍然惰性（`8x4s0/1/32/63` 在 P1 上仍是 11.6 µs 量级），符合预期：
  它要到 P6-04c 的 Algorithm D 才会变活；
- 多 limb 除数**完全未动**，仍是约 2.5 × 分子比特数次分配；
- §6 的所有权模型隐患本刀未修（由 `ad6bd639` 加固，且已证不可达）。
