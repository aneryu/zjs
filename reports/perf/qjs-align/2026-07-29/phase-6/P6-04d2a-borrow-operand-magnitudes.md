## 1. 机制：先证明「输入不可修改」，再借用

PRD 提醒不要简单删 `absClone()`，需先确认输入不被修改。逐臂核对：

| `divRemAbsAlloc` 的三条臂 | 是否写输入 |
|---|---|
| `compareAbs(lhs, rhs) == .lt` 早退 | 否 —— `lhs.cloneWithAllocator` |
| `rhs.limbs.len == 1` → `divRemAbsByLimbAlloc` | 否 —— 只读 `lhs.limbs` |
| `divRemAbsNormalizedLong` | 否 —— **先把两者拷进自己的 `u` / `v` scratch** 再动手 |

所以两次 clone 唯一产出的只是「清掉符号的副本」，而借用视图免费给同样的东西。
**因此不需要 PRD 备选方案里的「lhs 拷贝 / rhs 借用」拆分 —— 两个都能借。**

```zig
const lhs_abs = BigInt{ .negative = false, .limbs = lhs.limbs, .allocator = allocator };
const rhs_abs = BigInt{ .negative = false, .limbs = rhs.limbs, .allocator = allocator };
```

⚠️ **没有偷偷引入 ownership 优化**：这是纯借用，没有 refcount、没有 in-place scratch。

**守卫**：既有的 OOM sweep 断言「每次注入失败后调用者的操作数 limbs 逐字节未变」——
将来若有人写穿其中一个，会在那里失败，而不是悄悄破坏调用者的 BigInt。

## 6. 裁决

| 门槛 | 实测 | |
|---|---|---|
| `alloc/op` 6 → 4 | **多 limb 6→4，单 limb 4→2，memcpy 4→1** | ✓ |
| `div_8x4` ≥10% | direct-core **11.5%**；JS 8.4% | ✓（direct-core） |
| `div_16x8` ≥10% | direct-core **6.8%**；JS 8.3% | **✗** |
| `8×8` 无 ≥1% 回退 | **−17.4%** | ✓ |
| 纯度：算法计数完全一致 | 逐项相同 | ✓ |
| 正确性全套 | 全绿 | ✓ |

`16×8` 未达 10% 是可解释的、也是符合成本模型的：
它是本矩阵里**逐商位成本占比最高**的形态（9 个商位），
而这一刀削的是固定成本，因此对它帮助最小。
PRD 的分流条款「若 allocation 减少但 wall <5%，说明 allocator 不是主要部分」**不适用** ——
`16×8` 是 6.8%/8.3%，高于 5%。

## 8. 限制

- `div_16x8` 未达 10% 门槛（§6）；
- 借用的安全性由三条臂的逐一核对 + OOM sweep 守卫保证，**不是类型系统保证**；
- `memcpy` 4→1 而非 4→2 未追查；
- JS 层仍只有三个除法 case 加一个单 limb 哨兵，等宽形态在 JS 层未覆盖。
